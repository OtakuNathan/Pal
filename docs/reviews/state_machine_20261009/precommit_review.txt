New findings and fixes this round
1. OwnedLifecycleStep.run calls synchronous hooks on the owner loop; if a hook returns an already-started
   asyncio.Task, the old logic reported that it could not block, but did not save the Task. The next
   unload replay callback could repeatedly start cleanup. Now the Future/Task is kept first, then whether it can be awaited synchronously is decided; async shutdown can continue.
2. When synchronously awaiting a pending Task from another event loop, a callback failure did not consume the pending entry,
   and retries repeatedly read the same failure, unable to re-execute retryable cleanup. Now waiting timeout is distinguished from a
   completed callback failure, and the latter is consumed; both RuntimeError and a TimeoutError raised by the callback itself are covered.
   The regression precisely controls completion order via an event loop bridge, rather than guessing thread timing with fixed sleeps.
3. Checked the failure logs of recent remote CI: the macOS shell regression actually runs rg, but the runner lacks
   ripgrep, and the returned 127 was mistakenly treated as a business exit-code failure. The pytest job now explicitly ensures ripgrep exists,
   using apt on Ubuntu and Homebrew on macOS; installation is skipped if an executable is already present.

4. The widened same-process regression exposed module-generation isolation problems in 3 verifier tests: test classes are
   imported at collection time, while the monkeypatch targets are re-imported at test execution time; earlier
   plugin reloads had already replaced the module, so the patch landed on the new module while the old class was called, causing lost observations/wait timeouts.
   Now the class and its module are captured together, ensuring the tests observe the same generation of implementation. No production verifier changes.
   The first widened run was 495 passed / 3 failed; the original log is preserved as precommit-tests.log.

5. PluginScope's generic defer callback may also return an already-started Future/Task; the previous
   asyncio.run bridge could neither consume a Future nor avoid replaying the callback on retry. Now the scope
   keeps the same Future, retains all dependencies until it finishes, and consumes it only once after success; only after an explicit failure is
   retrying the callback allowed. Added two real scheduling regressions, for success and for retry after failure.
