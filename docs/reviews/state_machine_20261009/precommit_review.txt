本轮新发现与修复
1. OwnedLifecycleStep.run 在 owner loop 上调用同步 hook，若 hook 返回已经启动的
   asyncio.Task，旧逻辑会报无法阻塞，但没有保存 Task。下次卸载重放 callback
   可重复启动清理。现在先保留 Future/Task，再判断能否同步等待；异步关闭可接续。
2. 同步等待另一事件循环的 pending Task 时，callback 的失败没有消费 pending，
   重试会反复读取相同失败，无法重新执行可重试清理。现在区分等待超时与已完成
   回调失败，消费后者；RuntimeError 与 callback 自身抛出的 TimeoutError 都覆盖。
   回归通过事件循环 bridge 精确控制完成顺序，不靠固定 sleep 猜测线程时序。
3. 核对远端最近 CI 的失败日志，macOS 的 shell 回归真实执行 rg，但 runner 没有
   ripgrep，返回 127 被误作业务退出码失败。pytest job 现在显式确保 ripgrep 存在，
   Ubuntu 用 apt、macOS 用 Homebrew；已有可执行文件则跳过安装。

4. 扩大的同进程回归暴露 3 个 verifier 测试的模块代际隔离问题：测试类在
   collection 时导入，而 monkeypatch 目标在测试执行时重新导入；前面的插件
   reload 已替换模块，补丁打在新模块上，却调用旧类，造成观测丢失/等待超时。
   现在一起捕获类与其模块，保证测试观测同一代实现。没有修改生产 verifier。
   初次扩大回归为 495 passed / 3 failed，原日志保留为 precommit-tests.log。

5. PluginScope 的通用 defer 回调也可能返回已经启动的 Future/Task；原来的
   asyncio.run 桥接既不能消费 Future，又会在重试时重放 callback。现在 scope
   保留同一个 Future，未结束则保留全部依赖，成功后只消费一次；明确失败后才
   允许重试 callback。新增成功和失败后重试两个实际调度回归。
