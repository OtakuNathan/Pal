Pal 与 pal-shell-native 工具契约工程评审

执行摘要

1. 最高优先级是把自有公共 alias 统一为“动词 + 准确对象”。本次完整列出 223 个不同固定候选名称，逐项给出改名或保留建议；包含 Bunshin 角色限定工具，不代表同一会话同时暴露 223 个工具。命名要表达真实动作，不能把混合读写入口一律改成 get。
2. 搜索收益需要区分“词序一致”和“关键词覆盖”。现有 alias 词匹配不看顺序，纯重排不会提升这一层级；补全动作词、对象词才可能改变覆盖。精确匹配、前缀匹配和同分排序也会受改名影响。尚未执行搜索或模型行为基准，不能承诺命中率提升。
3. 第二优先级是让诊断事实真正到达模型正文。本次确认 10 类具体损失，另有 1 个条件性恢复提示缺口。先修 native 阻塞会话与 normalization 覆盖、write_file/delete_path 原因丢失等路径；保留有界诊断和安全恢复指针，不应将全部内部 structured 无条件回灌上下文。
4. 参数关系必须按实际实现写清，区分硬拒绝、静默优先级/忽略、运行状态前提。shell_session 的 action 白名单与标识符互斥尤其需要完整描述；多个 Bunshin task 字段现有说明与实际 actor 唯一活跃 Task 选择不一致。附录列出 43 个检查项，包含已正确说明的规则和正常组合，不等于 43 个缺陷；各项给出现状、建议描述和依据。
5. 成功路径的解释应放在稳定描述或成功结果里。remote_start 的动作完成不证明目标已就绪；remote_power 的 accepted/unknown 不证明关机完成。空结果解释、有效目标边界、usage unknown 等也不应只依赖失败指导触发。已经在 schema、skill、context_messages 或成功 payload 可见的语义另行标明，避免误报。

阅读顺序

- 附录 A：命名与搜索机制、完整当前 alias → 建议名称清单、shell_session 拆分选项及动态名称边界
- 附录 B：诊断信息在哪一层丢失、模型实际可见内容、最小修复；成功语义的确认项与反例
- 附录 C：参数组合与状态约束全清单、可直接使用的描述建议、应保留的自由组合

评审性质

这是固定源码版本上的只读静态评审。未改项目源码、未安装或运行项目、未运行测试，也未测量模型实际表现。所有改名、拆分、描述和渲染修改都是待实施建议。落地时应以最终模型正文和实际导出目录为验收对象。

附录 A 命名与搜索完整清单

搜索评分：改名能做什么、不能做什么

依据 runtime.py (https://github.com/OtakuNathan/Pal/blob/b76358fb1a8488abae4745d0826564d75e2415a1/src/pal/execution/runtime.py#L1003-L1096) 和 discovery_terms.py (https://github.com/OtakuNathan/Pal/blob/b76358fb1a8488abae4745d0826564d75e2415a1/src/pal/execution/discovery_terms.py#L10-L29)：

1. query/alias 小写；分词后按下划线、点、连字符拆分；轻量单复数归一；使用集合，不考虑词序。不做通用语义向量检索或词义理解
2. tier 5：query 与完整 alias 精确相等
3. tier 4：query 词集合与 alias 词集合相等
4. tier 3：query 所有词都在 alias 中，或无空格 query 是 alias 前缀
5. tier 2：alias 与 purpose 合并能覆盖全部 query 词
6. tier 1：至少一个词被 alias 或 purpose 覆盖；无覆盖的不返回
7. score = tier × 10000 + 总覆盖词数 × 100 + alias覆盖词数 × 10 + purpose覆盖词数；实际排序按这些分量降序，最后按 alias 字典序
8. namespace/family/module/tags 是过滤条件，不是正向任务匹配词。虽然编译 search_document 包含更多字段，当前评分代码只用 alias 和 purpose；use_when、failure_next_steps、schema 等也不参与正向评分
9. 默认返回上限 3；未显式传上限且最高 tier ≥ 2 时只保留最高 tier。改名可能改变被返回的结果，也可能改变字典序tie-break，但不是无条件更好

例如 browser_read → read_browser_page，加入 page 能直接覆盖“read browser page”；browser_read → read_browser 仅重排，对“browser read”无排序层级收益。browser_history → navigate_browser_history、shell_session 拆分成动作 alias，能使真实动作进入 alias；而把混合读写工具统一叫 get_* 会误导调用决策。

迁移注意：当前 capability 强制“恰好一个公共 alias”，不能简单在 aliases 中同时添加新旧名字。若要兼容旧名，需另行设计解析/迁移机制；本次没有建议修改内部地址。还需同步 guidance、next-tool hints、返回 affordance、示例、角色白名单中实际使用 alias 的部分以及测试/文档，防止出现仍提示旧名的恢复路径。

shell_session拆分：设计选项，尚未实现

“action + shell_session”的拆分建议可完整对应现有八个 action。下列是设计选项，尚未实现：
- read → read_shell_session：可带wait_ms；失败输出可重试导出，但不会重跑命令
- write → write_shell_session：必须带text；PTY输入有64KiB上限
- resize → resize_shell_session：必须带rows、columns
- terminate → terminate_shell_session：请求终止，不等价于已经终止
- release → release_shell_session：丢弃已完成的保留输出；不允许release正在运行的session，不等价于terminate
- watch → watch_shell_session：必须有正wait_ms，可带extend_by_ms
- extend → extend_shell_session：必须有正extend_by_ms；只延长已有有限deadline，无deadline时无需扩展；不是单纯等待
- unwatch → unwatch_shell_session：禁用后续主动通知，不等价于停止进程

NativeSessionInput要求session_id与output_ref二选一。output_ref仅支持read/release，且不允许wait_ms。因此拆分时必须保留这条互斥约束和输出恢复入口；read/ release可保留output_ref或另设输出专用alias。现有统一入口是INDIRECT_CONTROL；拆分需要独立schema/执行语义/affordance设计，不能靠改名自动得到正确的只读或重试属性。

附录 B 模型可见诊断与成功语义

范围与结论口径

范围是 Pal 内置工具、仓库内声明，以及 native 的 Python 宿主/remote 桥接和相关 C++ 拒绝生产点。不覆盖用户部署的自定义插件、独立 eye 实现或其他未取得源码的第三方工具。

结论来自静态源码路径。没有把“可能误判/多调用一次”写成已测得的模型行为；没有把 structured 中存在但正文没有的每个字段一律当成缺陷。执行状态、失败正文、恢复提示、输入契约、独立 context_messages、可按需读取的 detail/skill 都纳入判断。

摘要：清单一列出 10 类具体诊断信息损失，另列 1 个条件性恢复提示缺口。清单二区分 确定的默认成功路径语义缺口、声明位置不佳但别处已有语义、低优先级空结果解释/下一步建议。各项按成因归类，不能把类数当成缺陷调用点数量。

清单一：真实诊断损失

A1 · native 非空 blocking_sessions 被隐藏，反而取消了恢复入口 · P1

生产信息： ShellRejected 的 write_busy/result_capacity 分支把本地已跟踪 session_id、latest_status、watching 收集进 details.blocking_sessions。只有列表为空才添加 shell_status affordance：pal_plugin/pal_shell_native/runtime.py:456-479 (https://github.com/OtakuNathan/pal-shell-native/blob/f307c9614634dd62a97bd1429d967a1c55489896/pal_plugin/pal_shell_native/runtime.py#L456-L479)

附录 C 参数组合与状态约束

范围与结论

下文 P 表示 Pal 固定源码 (https://github.com/OtakuNathan/Pal/tree/b76358fb1a8488abae4745d0826564d75e2415a1)，N 表示 native 固定源码 (https://github.com/OtakuNathan/pal-shell-native/tree/f307c9614634dd62a97bd1429d967a1c55489896)。路径后的行号对应这两个版本。N 的 capabilities.py、tools.py、guidance.py、adapter.py、router.py 均在 pal_plugin/pal_shell_native/ 下。P 中 generated_tool_models.py 均指 src/pal/execution/generated_tool_models.py；同一章节内省略的 browser 文件路径基于 src/pal/web_fetch/，proactive 基于 src/pal/proactive/，v2 基于 src/pal/bunshin/v2/，lsp 基于 src/pal/lsp/；其他省略文件沿用紧邻上一条完整目录。

清单覆盖模型声明、公开 alias 注册、相关 handler/service 分支，包含作用域内的 Bunshin 工具。不能把以下三类混为一谈：
- 硬约束：组合不合法，调用被拒绝
- 选择/忽略：组合被接受，但某字段覆盖另一字段或根本不生效
- 状态前提：合法性取决于已选 session、任务、文件或目标的当前状态

结论：确有“schema 展示了单字段，却没展示组合规则”的缺口。最明显的是 shell_session、bunshin_start_workflow、proactive schedule、mcp_image_prepare，以及几个按 operation 复用的 browser/memory 工具。与此同时，browser_find 的 XOR、read_file 的 ranges 优先级、case memory 的 STAR 要求等已经说明，不能重复算成缺陷。

范围边界：不包含任意第三方动态 MCP/provider 自定义 schema；不穷举架构 artifact 文档与任意 policy/config 字典的递归语义；native C++ reactor、独立远端 worker 的全部平台状态机不在本附录的穷举声明内。以下为已检查工具表面的完整确认项，不代表所有可安装插件的约束全集。

A. Native shell 与 target

A1. shell_session：action 对应的精确参数矩阵

类型：硬约束。现状：部分说明，关键白名单缺失。

除 action、session_id/output_ref 外，允许的非 null 控制字段如下：

- action：read
  必填：无
  可选：wait_ms

- action：write
  必填：text，允许空字符串
  可选：无

- action：resize
  必填：rows、columns 同时填写
  可选：无

- action：terminate
  必填：无
  可选：无

- action：release
  必填：无
  可选：无

- action：watch
  必填：wait_ms > 0
  可选：extend_by_ms，可为 0

- action：extend
  必填：extend_by_ms > 0
  可选：无

- action：unwatch
  必填：无
  可选：无


其余非 null 字段全部拒绝。因此 write+wait_ms、resize+wait_ms、read+extend_by_ms 都不是自由组合。nullable 控制字段的显式 null 视为未提供。watch 的 wait_ms=0、extend 的 extend_by_ms=0 虽通过字段 ge=0，仍被 model_validator 拒绝。

当前 guidance 解释动作含义，但没有完整允许/禁止矩阵；字段描述也未补齐。validator 没有变成条件 JSON Schema。

建议 desc：
“read: optional wait_ms; write: text; resize: rows+columns; watch: positive wait_ms, optional extend_by_ms; extend: positive extend_by_ms; terminate/release/unwatch: no controls. Omit controls not listed for the action.”

组合必要性：这是多个不同动作共用一张字段表，适合拆 action 工具，或改成 discriminated union；不是有价值的任意组合。

证据：N pal_plugin/pal_shell_native/tools.py:22-43；guidance.py:36-61。

A2. shell_session：session_id/output_ref 与恢复分支

类型：硬约束。现状：output_ref 用途已说，XOR 和禁止等待没说全。

session_id 与 output_ref 必须恰好一个非 null。output_ref 只支持 read/release，禁止 wait_ms，连 wait_ms=0 也拒绝；结合 A1，此分支不接受任何其他控制字段。output_ref 还必须指向可用、已交付且导出失败的保留结果，否则 invalid_output_ref。

建议 desc：
“Supply exactly one of session_id or output_ref. With output_ref, use read or release and omit all controls, including wait_ms.”

组合必要性：可将 retained_output_read/release 与活 session 控制分开。

证据：N capabilities.py:62-73,139-151。

- 远端 sudo=true+tty=true 拒绝 privilege_pty_unsupported

A4. run_shell：wait 与 timeout 独立，不应杜撰不等式

证据：N tools.py:14-19；adapter.py:129-147；router.py:147-157；guidance.py:8-17。

A5. shell_session：状态前提，不是本次字段 XOR

B7. mcp_image_prepare：source/mode 的隐藏优先级

类型：选择/忽略，缺失可用 source 才拒绝。现状：明显缺失。

实际顺序：
1. url 非空且 mode=auto/url：直接返回 URL，忽略 artifact_id/path
2. 否则 artifact_id 非空：用 artifact metadata 中的本地路径覆盖 path
3. 否则用 path；没有可用本地路径则报 artifact_id, path, or url is required
4. mode=path 返回路径；mode=data_url 返回 data_url kind；artifact_id+auto/url 也返回 data_url kind；其他本地分支返回 base64 kind，payload 同时含 base64/data_url

所以 url 单独配 path/base64/data_url 不会先下载转换，会因无本地 source 失败。三种 source 同填不是 XOR，可能静默选错预期 source。

建议：
“Choose one source for clarity. url is used only with auto/url and takes precedence. Otherwise artifact_id overrides path; path/base64/data_url need a local file or artifact. auto uses URL as-is, artifact as data URL, or path as base64.”

组合必要性：宜分 source union 与输出格式；如新增 source XOR，属于行为变更，不能冒充已有规则。

证据：P src/pal/mcp/plugin.py:459-525；generated_tool_models.py ImagePrepareInput。

合并后的每个 binding：participant=profile 要 profile；participant=null 要非空 reason 且无 profile。有效 role map 必须恰好 architect/reviewer/implementation/verifier；前两个必须 profile，后两个必须同时 profile 或同时 null。

I. 单字段限制：不要与组合约束混列

- Native cmd 非空；wait 0..300000；timeout 1..2147483647；session_id >0 且 <=2^63-1；rows/columns 1..65535。text 的 UTF-8 字节数 <=65536 是 validator-only 限制，不是 schema 字符 maxLength。证据 N tools.py:14-43
